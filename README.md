# EJIS Terminal

**cmux의 다중 세션 작업 방식과 사용 경험을 바탕으로, Juik Eom이 직접 사용하기 위해 기획·제작한 Windows 터미널입니다.** 여러 AI 작업을 한 화면에서 살펴보고, 세션마다 역할을 나누어 일할 수 있습니다.

**[Windows 설치 파일 받기](https://github.com/brownailes/ejis-terminal/releases/latest)** · [처음 시작하기](#처음-시작하기) · [단축키](#단축키) · [변경 내역](CHANGELOG.md) · [문의하기](mailto:brownailes@gmail.com)

![독립된 터미널 세 개를 나란히 배치한 EJIS Terminal](docs/images/02-workspace.png)

> 이 문서의 스크린샷은 실제 앱의 macOS 개발 환경에서 예제 세션으로 촬영했습니다. 화면의 출력과 메시지는 사용법 설명용입니다. Windows 배포판에서는 PowerShell을 사용하며, 메뉴의 ⌘ 표시는 Ctrl로 바뀝니다. 실제 AI의 작업 결과를 보여주는 화면은 아닙니다.

## 주요 기능

| 하고 싶은 일 | EJIS Terminal에서 할 수 있는 일 |
| --- | --- |
| 여러 작업을 동시에 진행하기 | 최대 20개 독립 세션을 열고, 한 화면을 1단·2단·3단으로 바꿔 볼 수 있습니다. |
| 작업의 흐름 파악하기 | 세션 이름을 직접 정하거나 첫 입력을 바탕으로 자동 지정할 수 있습니다. |
| 마우스 사용 줄이기 | 세션 전환, 이름 변경, 복사·붙여넣기, 메시지 보내기를 단축키로 실행합니다. |
| 텍스트와 이미지 전달하기 | 터미널의 선택한 내용을 복사하고, 클립보드 텍스트나 이미지 파일 경로를 입력합니다. |
| 세션 사이에 메모 남기기 | 보낸 시각과 확인 여부를 기록하고, 메시지 연결 관계를 그림으로 볼 수 있습니다. |
| 내게 맞는 화면 만들기 | 테마, 3단계 글자 크기, 투명도 5% 토글과 미리듣기가 있는 알림음 3종을 선택합니다. |
| 설정 차이 줄이기 | Windows에서 사용자 PowerShell 프로필을 불러오지 않고 공통 실행 옵션으로 시작합니다. 설치한 AI 도구와 계정은 각 PC의 것을 사용합니다. |
| Google 계정 연결하기 | 승인된 Google 계정으로 로그인하면 Claude Code·Codex·Antigravity CLI 설치를 자동으로 준비합니다. |
| 사용자의 진행 상황 확인하기 | 관리자 모드에서 화면 공유를 허용한 사용자를 선택해 EJIS Terminal 창을 읽기 전용으로 확인합니다. |

## 처음 시작하기

### 1. 설치 파일 받기

1. **[최신 버전 페이지](https://github.com/brownailes/ejis-terminal/releases/latest)**를 엽니다.
2. `Assets`에서 `EJIS-Terminal-버전-x64-setup.exe`를 받아 실행합니다. `Source code` 압축 파일은 설치 파일이 아닙니다.
3. 설치 위치를 정하고 안내에 따라 설치합니다.
4. 바탕화면의 **EJIS Terminal**을 실행합니다.

현재 배포 대상은 **Windows 11 x64**입니다. 0.2.0부터 Google 로그인이 필요하며, GitHub 계정은 필요하지 않습니다. **Electron 실행 환경이 설치 파일에 포함되어 있으므로 별도 Electron 설치나 사전 실행이 필요하지 않습니다.** 설치·제거 프로그램과 실행 파일, 창 및 바로가기에는 EJIS CI를 사용합니다. 현재 설치 파일에는 코드 서명이 없어 Windows에서 게시자를 확인하지 못했다는 안내가 나타날 수 있습니다. 이 저장소의 릴리스에서 받은 파일인지 확인합니다.

### 2. Windows 상태 확인하기

앱이 시작되면 Thinking Orbs 애니메이션과 함께 Windows 업데이트 상태를 확인합니다. 필요한 업데이트나 재시작이 없으면 **Untitled 01** 세션으로 넘어갑니다. 세션을 우클릭해 작업에 맞게 이름을 바꿀 수 있습니다. 업데이트가 필요하면 안내에 따라 Windows 설정에서 설치한 뒤 다시 확인합니다.

앱이 Windows 업데이트를 자동으로 설치하거나 PC를 재시작하지는 않습니다. 인터넷 연결, 업데이트 서비스, 조직의 정책에 따라 확인하지 못할 수 있습니다. 확인 대상은 Windows Update가 현재 제공하는 필수 소프트웨어 업데이트이며, 선택 업데이트나 드라이버는 제외합니다. 모든 PC가 동일한 Windows 버전이라는 뜻은 아닙니다.

### 3. 관리자 승인 후 작업하기

Windows 배포판은 시작할 때 관리자 승인을 요청하며, 열린 터미널과 그 안의 명령도 관리자 권한으로 실행됩니다. 승인을 취소하면 앱이 열리지 않습니다. 다른 관리자 계정으로 승인하면 해당 계정의 환경을 사용할 수 있습니다.

관리자 권한과 AI 도구의 작업 승인은 별개입니다. AI 도구의 승인·자동 실행 설정은 각 도구에서 선택하며, EJIS Terminal이 이를 자동 실행 모드로 바꾸지는 않습니다.

### 4. 터미널에서 바로 입력하기

![처음 실행하면 다크 모드의 터미널 한 개가 열립니다](docs/images/01-start.png)

처음에는 **다크 모드 · 터미널 1개 · 1단 화면**으로 시작합니다. 0.1.7부터 터미널 줄간격은 **1.2배**로 적용합니다. 터미널 안을 클릭하고 명령을 입력합니다. 별도 입력창은 없습니다.

### 5. Google 계정으로 로그인하기

![Hello, 인사와 초록색 점선 Google Login 버튼](docs/images/14-google-login.png)

따뜻한 밝은 배경에 **Hello, + Google Login**을 표시합니다.

0.3.0부터 Google 로그인은 **EJIS Terminal 전용 인증 서버**에서 독립적으로 진행합니다. 승인 계정 목록과 앱 세션도 EJIS에서 관리합니다. 다른 서비스에 로그인하거나 로그아웃해도 EJIS 로그인 상태는 바뀌지 않습니다.

**Google Login**을 누르면 브라우저에서 승인된 Google 계정을 확인합니다. 앱과 브라우저의 확인 코드가 같은지 확인한 뒤 **EJIS Terminal 로그인**을 누릅니다. 로그인은 현재 앱 실행에만 유지됩니다. 0.2.x를 사용 중이면 먼저 최신 버전으로 업데이트해주세요.

로그인하면 Claude Code, Codex, Antigravity CLI를 공식 배포 경로에서 자동으로 준비합니다. 상단 계정 버튼의 **AI 도구**에서 설치·버전 확인 결과를 보고 재시도하거나 실행할 수 있습니다. 기관의 네트워크·설치 정책에 따라 준비가 실패할 수 있으며, 앱이 보안 설정이나 PowerShell 실행 정책을 낮추지는 않습니다.

각 AI 서비스를 처음 실행할 때는 **본인 계정으로 별도 인증**해야 합니다. Google 로그인만으로 세 서비스의 구독이나 API 이용 권한이 생기지는 않습니다. 다른 사용자의 API 키·구독 자격 증명은 사용자 PC에 전달하지 않습니다. Antigravity는 `agy` CLI를 실행하며 별도 IDE 화면을 앱에 포함하지 않습니다.

관리자 계정에는 **접속자 화면** 탭이 표시됩니다. 사용자가 **화면 공유**를 선택해 확인한 뒤, 해당 사용자를 선택하면 **EJIS Terminal 창만** 확인하며, 다른 앱·PC 전체 화면이나 원격 키보드·마우스 제어는 제공하지 않습니다. 열람 중에는 해당 앱에 안내가 표시되며 **화면 공유 중지**로 중단할 수 있습니다. 최신 화면 한 장을 연결 서버로 전송하며 LLM에는 보내지 않습니다. 열람 종료·공유 중지·로그아웃 시 접근을 차단하고, 만료된 화면은 제공하지 않습니다.

각 세션 아래에는 Codex CLI 계정이 제공하는 사용량을 표시합니다. **계정 전체 사용량**으로, 해당 세션의 과금액이 아닙니다. Claude Code·Antigravity 사용량은 아직 연결하지 않았습니다.

## 세션과 화면 나누기

- **새 터미널**을 누르면 독립된 세션이 열립니다. 세션마다 실행 중인 명령과 작업 폴더를 따로 관리합니다.
- **폴더 선택**으로 새 작업의 시작 폴더를 정합니다.
- **화면 나누기**에서 1단·2단·3단을 선택합니다.
- 왼쪽 목록에서 세션을 선택하거나 `Ctrl+1`부터 `Ctrl+9`, `Ctrl+Tab`으로 이동합니다.
- 세션 이름은 직접 바꿀 수 있습니다. 자동 이름은 첫 입력을 참고하므로, 민감한 내용이 있다면 이름을 확인합니다.
- 세션 종료는 해당 터미널의 프로세스를 종료합니다. 앱을 다시 열어도 이전 실행 상태가 복원되지는 않습니다.

### 세션 메뉴

![세션 메뉴와 기능별 단축키](docs/images/03-session-menu.png)

왼쪽 세션을 **우클릭**하거나 `···`를 누르면 메뉴가 열립니다. 이름 변경, 이동, 알림 관리, 복사·붙여넣기, 화면 지우기, 내용 저장, 시작 폴더 열기, 메시지와 종료 기능을 사용할 수 있습니다. 메뉴 바깥을 클릭하거나 `Esc`를 누르면 닫힙니다.

상단 메뉴와 세션 메뉴, 설정 항목에는 같은 굵기의 미니멀 선 아이콘을 표시합니다. 아이콘 옆의 이름으로 기능을 함께 확인할 수 있습니다.

메뉴가 열려 있을 때는 그 메뉴의 세션에 단축키가 적용됩니다. 메뉴가 닫힌 상태에서는 현재 선택한 세션에 적용됩니다.

## 복사와 붙여넣기

- 마우스로 터미널의 텍스트를 드래그해 선택한 뒤 **Ctrl+C**를 누르면 복사됩니다.
- 선택한 텍스트가 없으면 **Ctrl+C**는 터미널의 실행 중단 신호로 동작합니다.
- **Ctrl+V**로 클립보드 텍스트를 붙여넣습니다. 여러 줄의 내용은 확인 안내를 거쳐 입력합니다.
- 이미지를 복사한 뒤 붙여넣으면 PC에 PNG 파일로 저장하고, 그 파일의 경로를 터미널에 넣습니다. **이미지 붙여넣기** 메뉴도 사용할 수 있습니다. 한 이미지의 크기는 최대 30MB입니다.
- 이미지를 AI 서비스에 자동 업로드하지는 않습니다. 경로를 받은 AI 도구가 이미지를 읽는 방식과 지원 여부는 해당 도구에 따라 달라집니다.
- **전체 선택**이나 **터미널 내용 저장**으로 현재 남아 있는 터미널 버퍼를 가져올 수 있습니다. 버퍼는 최대 10,000줄이며, 이미 사라진 출력이나 AI 도구의 별도 화면 전체를 복원하지는 않습니다.
- **Shift+Tab**은 터미널 안의 프로그램에 전달됩니다. 어떤 기능으로 동작하는지는 실행 중인 도구가 결정합니다.

0.1.6에서는 클립보드 API 변경으로 붙여넣기 시 발생하던 `availableFormats` 오류를 수정했습니다.

## 세션 ID와 협업 기록

### 실제 세션 ID 확인하기

![복사한 세션 ID와 프로세스 번호를 확인하는 안내](docs/images/06-session-id.png)

**세션 ID 복사**를 누르면 실제 열린 세션의 UUID가 복사되고, 복사한 값과 프로세스 번호가 화면에 표시됩니다. 이 ID는 EJIS Terminal 내부의 세션 식별자이며, AI 서비스의 대화 ID나 로그인 토큰이 아닙니다.

### 메시지 보내고 흐름 확인하기

![메시지를 주고받은 세션과 확인 시각을 보여주는 협업 기록](docs/images/05-collaboration.png)

1. 세션 메뉴에서 **세션에 메시지 보내기**를 선택합니다.
2. 받을 세션을 고르고 내용을 입력합니다.
3. 받는 세션에 표시와 소리로 알림이 전달됩니다. 소리는 설정과 세션의 알림 상태에 따라 달라집니다.
4. **받은 메시지 보기**로 확인하면 읽은 시각이 기록됩니다.
5. 상단의 **협업 기록**에서 보낸 사람, 받는 사람, 시각, 내용, 확인 여부를 함께 확인합니다.

**최근 메시지** 탭에는 메시지 수·참여 세션 수·열지 않은 메시지 수와 시간순 기록을 표시합니다. 전체 본문과 세션 ID는 각 기록을 펼쳐 확인합니다. **연결 그림** 탭에서는 메시지를 주고받은 관계를 확인합니다. 두 탭은 창 위치를 유지하고 내용만 스크롤합니다.

![메시지 방향과 세션 연결을 확인하는 연결 그림 탭](docs/images/11-collaboration-graph.png)

연결 그림의 화살표는 실제로 보낸 메시지의 방향을 나타냅니다. 기록은 최근 200개 메시지, 그림은 최대 12개 세션을 보여주며 세션별로 골라 볼 수 있습니다. 전체 기록은 JSONL 파일로, 연결 그림은 SVG 이미지로 저장할 수 있습니다.

이 기능은 **같은 앱 안의 세션 사이에서 사용자가 주고받는 메시지**를 기록합니다. 메시지를 터미널 명령으로 자동 실행하거나, AI의 작업 완료를 자동 판정하거나, 다른 PC의 세션과 연결하지는 않습니다. ‘확인’은 받은 메시지 화면을 열었다는 뜻입니다.

## 화면과 알림 설정

![글자 크기 버튼, 투명도 토글과 알림음 미리듣기가 있는 설정](docs/images/04-settings.png)

**설정**에서 다음 항목을 바꿀 수 있습니다.

| 항목 | 선택 범위 |
| --- | --- |
| 화면 테마 | 다크 · 라이트 · 시스템 설정 |
| 터미널 글자 크기 | 작게 12 · **보통 14(기본)** · 크게 16 버튼 |
| 알림 | 켜기·끄기 토글, 맑은 벨 · 부드러운 울림 · 가벼운 세 음 중 선택과 미리듣기 |
| 투명도 | 켜면 5%, 끄면 불투명. 앱 창 전체에 적용 |

설정은 저장 버튼을 눌러 적용하며, 취소하면 기존 설정을 유지합니다. 알림 소리가 꺼져 있어도 미리듣기를 실행할 수 있습니다. 메시지 수신이나 터미널의 벨 신호에 맞춰 알림을 표시합니다. 모든 AI 도구의 승인 요청을 자동으로 인식하는 기능은 아닙니다.

## 업데이트하기

![새 버전 안내와 상대 배포 날짜를 표시한 업데이트 버튼 예시](docs/images/08-update-example.png)

이 화면의 버전과 배포 시각은 버튼의 상태를 보여주기 위한 예제입니다. 실제 앱은 업데이트 서버에서 받은 버전과 배포일을 표시합니다.

**지금 최신 버전이에요** 안내는 클릭하면 닫힙니다. 작은 **업데이트 확인** 버튼으로 다시 확인할 수 있으며, 새 버전이 발견되면 강조 안내가 다시 나타납니다.

**새 버전 자동 확인**이 켜져 있으면 앱을 시작할 때와 이후 약 15분마다 새 버전을 확인합니다. **상단 협업 기록 아래의 업데이트 버튼**으로 직접 확인할 수도 있습니다.

새 버전이 있으면 **상단 협업 기록 아래의 전용 버튼이 페일 핑크로 강조**됩니다. 다운로드와 설치는 사용자가 선택합니다. 작업을 저장한 뒤 설치합니다. 다운로드만 했다고 자동 설치하거나, 앱을 닫을 때 임의로 설치하지 않습니다.

GitHub에 커밋하는 것만으로 설치된 앱이 바뀌지는 않습니다. Windows 빌드와 검증을 마친 새 버전이 릴리스로 공개되어야 앱이 업데이트를 안내합니다. 앱 업데이트와 Windows 운영체제 업데이트는 따로 확인합니다.

버튼에는 확인 중·다운로드 진행률·설치 준비 상태를 표시합니다. 최신 버전의 배포일은 **2시간 전 배포**, **3일 전 배포**처럼 나타내며, 날짜 위에 마우스를 올리면 정확한 시각을 확인할 수 있습니다. 배포일을 받지 못한 경우 날짜를 추측하지 않고 정보가 없다고 표시합니다.

### 업데이트 설정

![현재 버전과 변경 내역, 자동 확인 옵션이 있는 업데이트 설정](docs/images/12-update-settings.png)

**설정 → 업데이트**에서 설치된 버전과 새 버전 확인 결과를 살펴봅니다. **변경 내역 보기**는 [버전별 개선 사항](CHANGELOG.md)을 엽니다. 자동 확인을 끄거나 켠 뒤 **저장**하면 적용됩니다. 자동 확인을 꺼도 **업데이트 확인** 버튼으로 직접 확인하고 설치할 수 있습니다.

자동 확인은 기본으로 켜져 있으며, 새 버전을 찾는 기능입니다. 다운로드와 설치는 직접 선택합니다. 이 설정은 앱 시작 시 실행하는 Windows 업데이트 확인과 별개입니다. 설정 탭을 바꿔도 창과 탭·저장 버튼의 위치를 유지하며 내용만 스크롤합니다.
